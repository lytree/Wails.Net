## 1. Linux 实机

### L1 桌面门户外观读取（`#6072`）

**前置条件**

- Linux 桌面会话（GNOME/KDE 等），D-Bus **session bus** 可用。
- 已安装并运行 `xdg-desktop-portal`（GNOME 后端 `xdg-desktop-portal-gnome`；KDE 为 `xdg-desktop-portal-kde`）。
- GTK4 + WebKitGTK 运行库；Demo 可启动。
- 安装 `gdbus`（`libglib2.0-bin`）。

**执行步骤**

```bash
cd /mnt/f/Code/Dotnet/Wails.Net

# 1) 确认门户接口与两个方法存在（ReadOne 回退路径只在缺少 Read 时才会走）
gdbus introspect --session \
  --dest org.freedesktop.portal.Desktop \
  --object-path /org/freedesktop/portal/desktop \
  | grep -E 'Read|ReadOne'

# 2) 直接读取当前值（variant 内 uint32：0=无偏好，1=暗色，2=亮色）
gdbus call --session \
  --dest org.freedesktop.portal.Desktop \
  --object-path /org/freedesktop/portal/desktop \
  --method org.freedesktop.portal.Settings.Read \
  org.freedesktop.appearance color-scheme

# 3) 切到暗色（GNOME；KDE 用系统设置切换）
gsettings set org.gnome.desktop.interface color-scheme 'prefer-dark'

# 4) 启动 Demo（Linux 使用 net10.0 目标）
WAILS_DEBUG=1 dotnet run --project examples/Wails.Net.Demo/Wails.Net.Demo.csproj -f net10.0
```

在自动打开的 DevTools Console 中执行：

```javascript
// 读取暗色状态与耗时
const t = performance.now();
const dark = await wails.call('application.isDarkMode', []);
({ dark, ms: Math.round(performance.now() - t) })

// 服务端可用的屏幕/外观信息（辅助确认平台已加载）
await wails.call('application.getScreens', [])
```

切到亮色后重复：

```bash
gsettings set org.gnome.desktop.interface color-scheme 'prefer-light'
# 等待 1 秒后在 Console 再次执行 application.isDarkMode
```

验证 500ms 超时回退：

```bash
# 终端 B：让门户进程挂起，模拟门户无响应
pkill -STOP -x xdg-desktop-portal

# 回到 DevTools 执行上方的计时调用；预期 ms < 700，且返回值来自 gsettings 回退链

# 恢复
pkill -CONT -x xdg-desktop-portal
```

**预期结果**

- 门户返回 uint32 = 1 时，`isDarkMode` 为 `true`；返回 2 时为 `false`；返回 0 时 `LinuxAppearancePortal.TryReadColorSchemeIsDark()` 返回 `null`，继续走 gsettings / `GTK_THEME` / `COLOR_SCHEME` 回退链（见 [LinuxPlatformApp.cs](file:///f:/Code/Dotnet/Wails.Net/src/Wails.Net.Application.Linux/LinuxPlatformApp.cs#L209-L252)）。
- 门户正常时调用耗时通常 < 100ms；门户被 `SIGSTOP` 时仍应在约 500ms 内返回（不会永久挂起）。
- `ReadOne` 回退：仅当门户缺少 `Read` 方法时触发。主流 GNOME/KDE 门户同时提供 `Read` 与 `ReadOne`，因此**无法在常规桌面上强制走该分支**；本项只能做代码审查确认（[LinuxAppearancePortal.cs](file:///f:/Code/Dotnet/Wails.Net/src/Wails.Net.Application.Linux/LinuxAppearancePortal.cs#L54-L133)），需在结论中标注“Read 主路径已实机验证，ReadOne 回退仅代码审查”。

**失败排查**

- `isDarkMode` 恒为 `false`：先确认 `gdbus call` 有返回值；再检查 [LinuxAppearancePortal.cs](file:///f:/Code/Dotnet/Wails.Net/src/Wails.Net.Application.Linux/LinuxAppearancePortal.cs#L70-L78) 的 `MapColorScheme` 是否收到 `0/1/2`（若门户返回字符串或嵌套 variant，映射会落空）。
- 调用卡住超过 1 秒：检查 [LinuxAppearancePortal.cs](file:///f:/Code/Dotnet/Wails.Net/src/Wails.Net.Application.Linux/LinuxAppearancePortal.cs#L85-L133) 的 500ms `CancellationTokenSource` 是否在 `Read`/`ReadOne` 两个分支都生效。
- 平台未加载（命令不存在）：确认 `WAILS_DEBUG` 启动日志中平台为 Linux，且 `Gdk.Display` 初始化成功。
- 无门户环境：`LinuxPlatformApp.IsDarkMode` 会在 portal 失败后回退 gsettings；用 `gsettings get org.gnome.desktop.interface color-scheme` 对比。

**证明条目**：`#6072`（§12.2 第 4 条；§12.4 第 4 条；§12.5 “未验证”清单）。

### L2 多 DPI 屏幕下的 DIP 坐标（`#6346` Linux）

**前置条件**

- **X11 会话**（`XDG_SESSION_TYPE=x11` 或 `GDK_BACKEND=x11`）。Wayland 下应用不能直接设置窗口位置，`wmctrl` 路径会被跳过。
- 安装 `wmctrl`、`x11-utils`；至少两台显示器且缩放比例不同（例如 1.0 + 2.0），或单屏设为 2.0 缩放。
- Demo 可启动。

**执行步骤**

```bash
cd /mnt/f/Code/Dotnet/Wails.Net

# 1) 确认后端与显示器几何/缩放
echo "$XDG_SESSION_TYPE"
wmctrl -m
xrandr --listmonitors

# 2) 启动 Demo（Debug 模式自动开 DevTools）
WAILS_DEBUG=1 dotnet run --project examples/Wails.Net.Demo/Wails.Net.Demo.csproj -f net10.0
```

DevTools Console：

```javascript
// 先读取屏幕（DIP 几何 + 缩放因子）
await wails.call('application.getScreens', [])

// 1x 屏：设置并读回
await wails.window.setPosition(300, 200)
await wails.window.getPosition()

// 居中（应落在窗口当前所在显示器的几何中心）
await wails.window.centre()
await wails.window.getPosition()
```

外部终端验证物理坐标：

```bash
wmctrl -lG | grep 'Wails.Net Demo'
```

多屏/高 DPI 用例：

```javascript
// 把窗口放到第二块屏的 DIP 坐标（示例：主屏宽 1920 DIP，第二屏 x=1920）
await wails.window.setPosition(1920 + 120, 160)
await wails.window.getPosition()   // 应精确返回 (2040, 160)
await wails.window.centre()        // 应在窗口中心命中的屏幕上居中
```

**预期结果**

- `getPosition()` 在 **X11** 下返回**调用方传入的 DIP**（代码缓存 DIP，见 [LinuxWebviewWindow.cs](file:///f:/Code/Dotnet/Wails.Net/src/Wails.Net.Application.Linux/LinuxWebviewWindow.cs#L1806-L1810)）；在 **Wayland** 下按上游语义返回 `(0, 0)`（见下方「已知限制」）。
- `wmctrl -lG` 的物理坐标满足 `physical ≈ floor(DIP × 目标屏 ScaleFactor)`（允许窗口管理器边框/标题栏带来的数十像素偏差）：
  - 1.0 缩放：`x≈300`、`y≈200`；
  - 2.0 缩放：`x≈600`、`y≈400`。
- `setPosition()` 只移动、不改变尺寸（`wmctrl -e` 的宽/高传 `-1`），与上游 `move()` 语义一致；窗口被用户手动改过尺寸后也不会跳回默认尺寸。
- `getSize()` 优先返回窗口已分配的实际尺寸（GTK4 `gtk_widget_get_width/get_height`），仅在尚未布局时回退默认尺寸（对齐上游 `size()`）；用户或窗口管理器改变尺寸后可如实读回。
- `centre()` 的目标屏为窗口**当前所在显示器**（`Gdk.Display.GetMonitorAtSurface`，对齐上游 `getCurrentMonitor()`；尚未 realize 时回退首显示器），窗口中心 = 目标屏 `Geometry` 中心：`x = gx + (gw - w)/2`、`y = gy + (gh - h)/2`（DIP，`w/h` 为 `getSize()` 的实际尺寸），再由 [MoveWindowByDipBounds](file:///f:/Code/Dotnet/Wails.Net/src/Wails.Net.Application.Linux/LinuxWebviewWindow.cs#L2311-L2351) 换算物理像素。
- 负坐标显示器（位于主屏左侧/上方）应能正确命中，不会被截断为 0。

**本轮修复关联验证（2026-11-07，对齐上游 `webview_window_linux.go` / `linux_purego.go`）**

- 多屏下把窗口置于第二屏后调用 `centre()`，应居中在**第二屏**（窗口当前所在显示器），而不是固定主屏。
- 创建选项 `Centered=true` 或 `X/Y=-1` 时，窗口 `Show()` 后应自动居中；显式 `X/Y` 时按 DIP 坐标定位；`Maximised`/`Minimised`/`Fullscreen` 起始状态按选项生效。
- 创建选项 `AlwaysOnTop=true` 时，置顶在 `Show()`（present）之后才应用，不应在窗口尚未显示时命中其它窗口。
- `window.setHTML()` 加载的页面（基线 `wails://localhost/`）应能正常调用绑定；若 IPC 返回 403，检查 [LinuxIpcOriginGuard.cs](file:///f:/Code/Dotnet/Wails.Net/src/Wails.Net.Application.Linux/LinuxIpcOriginGuard.cs) 的同源判定。
- 通过窗口管理器/标题栏改变最大化、最小化、全屏后，应用层应收到对应的窗口事件（三态观察者派发，不再由程序化调用直接派发）。

**已知限制（需在结论中标注）**

- **Wayland 不支持定位（平台固有限制，非移植缺陷）**：Wayland 协议不允许客户端设置顶层窗口位置，位置由 compositor 决定。上游 Wails v3.1.0 的 `window_move_x11` 同样在非 X11 直接返回、`position()` 返回 `(0, 0)`；本实现与之一致：`LinuxBackendDetector.SupportsWindowPositionControl()` 仅在 X11 返回 true（[LinuxBackendDetector.cs](file:///f:/Code/Dotnet/Wails.Net/src/Wails.Net.Application.Linux/LinuxBackendDetector.cs#L147)），Wayland 下 `setPosition`/`centre` 不移动窗口，`getPosition` 返回 `(0, 0)`（自 2026-11-07 起不再返回缓存的请求坐标）。**不要**把 Wayland 下「窗口不动」记为 ❌；若产品必须支持 Wayland 定位，需引入 compositor 专有协议（如 `wlr-layer-shell`），超出上游与 GTK4 的能力范围，应另行立项。
- `SetSize` 在 Linux 仅调用 `Gtk.Window.SetDefaultSize`（[LinuxWebviewWindow.cs](file:///f:/Code/Dotnet/Wails.Net/src/Wails.Net.Application.Linux/LinuxWebviewWindow.cs#L1362-L1370)），对已显示窗口通常不改变尺寸。这与上游 Wails v3.1.0（`linuxWebviewWindow.setSize` → `gtk_window_set_default_size`）完全一致，且 GTK4 已移除 `gtk_window_resize`，**属于平台固有限制而非移植缺陷**；本项不要用 `setSize` 作为 DIP 判定依据，需要读尺寸时用 `getSize()`（已改为优先读实际分配尺寸）。

**失败排查**

- 窗口完全不动：先看 `wmctrl -m` 是否为 X11；Wayland 下预期不动（平台限制，不是失败）；再确认 `wmctrl` 在 PATH 中。
- 移动了但坐标不对：检查 [LinuxDipCoordinates.cs](file:///f:/Code/Dotnet/Wails.Net/src/Wails.Net.Application.Linux/LinuxDipCoordinates.cs) 的 `NormalizeScaleFactor`/`DipToPhysical`，以及 [CollectMonitorInfos](file:///f:/Code/Dotnet/Wails.Net/src/Wails.Net.Application.Linux/LinuxWebviewWindow.cs#L2358-L2395) 读取的 `monitor.Geometry`（DIP）与 `monitor.ScaleFactor`。
- 多屏选错显示器：检查 [SelectTargetMonitor](file:///f:/Code/Dotnet/Wails.Net/src/Wails.Net.Application.Linux/LinuxDipCoordinates.cs) 的命中/最近距离回退。
- `wmctrl` 报 “Cannot find window”：标题必须与 `_options.Title` 完全一致（Demo 为 `Wails.Net Demo ...`）；用 `wmctrl -l` 列出实际标题。

**证明条目**：`#6346`（§12.2 第 12 条；§12.4 第 9 条；§12.5 “未验证”清单）。

### A2 Android 单元/插桩测试路径（❌ 决定不补测试宿主）

**前置条件**

- 同 A1（工作负载 + 设备/模拟器）。

**执行步骤（先确认现状）**

```powershell
Set-Location "f:\Code\Dotnet\Wails.Net"

# 仅编译验证
dotnet build tests/Wails.Net.Application.Android.Tests/Wails.Net.Application.Android.Tests.csproj -c Debug

# 尝试部署运行（预计失败；用于取证）

  -f net10.0-android36.0
```

**预期结果（当前实现）**

- `dotnet build` 通过。
- `dotnet run` **不能**在设备上启动测试：该测试项目没有 `MainActivity`、没有 `Properties/AndroidManifest.xml`、csproj 未声明 `ApplicationId`/`AndroidApplication`（见 [Wails.Net.Application.Android.Tests.csproj](file:///f:/Code/Dotnet/Wails.Net/tests/Wails.Net.Application.Android.Tests/Wails.Net.Application.Android.Tests.csproj) 与目录清单）。因此当前仓库缺少 Android 设备端测试宿主。
- 同时 `AndroidWebviewWindowFixture.HasRealGuiEnvironment` 恒为 `false`（[AndroidWebviewWindowFixture.cs](file:///f:/Code/Dotnet/Wails.Net/tests/Wails.Net.Application.Android.Tests/AndroidWebviewWindowFixture.cs#L61)），即使设置 `WAILS_RUN_GUI_TESTS=1`，基类 `CreateWindow` 仍会抛 `SkipTestException`（[WebviewWindowContractTests.cs](file:///f:/Code/Dotnet/Wails.Net/tests/Wails.Net.Application.GuiContract.Tests/WebviewWindowContractTests.cs#L61-L64)）：按源码统计，109 项契约中约 **5 项**在创建窗口前提前返回可通过，其余约 **104 项**仍标记为跳过——**不能判定“GUI 契约变绿”**。
- 仓库没有独立 `androidTest`/instrumentation 工程；插桩路径当前**不存在**。

**决策（2026-11-05）：不补齐设备端测试宿主**

- 依据：补齐最小宿主需新增 `MainActivity` + `ApplicationId` + `AndroidManifest.xml`（以及把测试结果回写 logcat/文件的入口），属 Android 专有脚手架；本机未安装 `android` 工作负载（4 个项目 `NETSDK1147`），**改动无法编译验证**，风险高于收益。
- 因此 `HasRealGuiEnvironment` 保持 `false`，仅改写 XML 注释说明能力边界（**不返回 true 伪装可跑**，未降低任何断言强度）。
- 建议路径（后续实现时）：`MainActivity.OnCreate` 启动 TUnit 入口，结果写入 logcat 或应用私有文件，由 `adb` 脚本判定。
- 详见 `docs/development/wails-v3-beta-comparison.md` §12.4 第 15 条。

**结论写法**

- A2 记为 **❌ 不补（已评估决策）**，不要写“验证通过即可”。
- 设备端功能验证改由 A3 E2E 覆盖。

**失败排查**

- `dotnet run` 报 “No activity found / no launchable activity”：即上述缺 `MainActivity`。
- 报缺少 manifest/ApplicationId：补测试宿主工程（属实现工作，不在本清单修改范围）。

**证明条目**：§12.5 Android 4 项目跳过；不直接对应 release note 编号。

**证明条目**：Android WebView/IPC 回归；配合 §12.5 Android 项目解除跳过。
