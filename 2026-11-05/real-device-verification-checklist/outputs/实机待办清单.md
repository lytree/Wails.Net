### L1 [Linux] 桌面门户外观读取 — §12 `#6072`

- [ ] **L1-1 确认门户同时提供 `Read` 与 `ReadOne`**
  - 前置：图形会话 + D-Bus session bus + `xdg-desktop-portal` 正在运行。
  - 命令：
    ```bash
    gdbus introspect --session \
      --dest org.freedesktop.portal.Desktop \
      --object-path /org/freedesktop/portal/desktop | grep -E 'Read|ReadOne'
    ```
  - 通过判定：输出中同时出现 `Read` 与 `ReadOne`（主流 GNOME/KDE 均如此）。
  - 失败先看：`src/Wails.Net.Application.Linux/LinuxAppearancePortal.cs` 的 `TryReadColorSchemeIsDark`（`Read` → `ReadOne` 回退分支）。

- [ ] **L1-2 记录门户当前值（基线）**
  - 命令：
    ```bash
    gdbus call --session --dest org.freedesktop.portal.Desktop \
      --object-path /org/freedesktop/portal/desktop \
      --method org.freedesktop.portal.Settings.Read \
      org.freedesktop.appearance color-scheme
    ```
  - 通过判定：返回 `(<<uint32 N>>,)`，`N=1`（暗色）或 `N=2`（亮色）或 `N=0`（无偏好）。
  - 失败先看：门户未运行或缺少 `xdg-desktop-portal-gnome` 后端，先 `systemctl --user status xdg-desktop-portal`。

- [ ] **L1-3 切到暗色并核对 Demo 返回值**
  - 命令（终端 A）：
    ```bash
    gsettings set org.gnome.desktop.interface color-scheme 'prefer-dark'
    WAILS_DEBUG=1 dotnet run --project examples/Wails.Net.Demo/Wails.Net.Demo.csproj -f net10.0
    ```
  - 操作（DevTools Console，Demo 启动后自动打开）：
    ```javascript
    const t = performance.now();
    const dark = await wails.call('application.isDarkMode', []);
    ({ dark, ms: Math.round(performance.now() - t) })
    ```
  - 通过判定：`dark === true`。若 L1-2 的值为 2，则预期 `dark === false`；若为 0，预期继续回退到 gsettings（与 `gsettings get org.gnome.desktop.interface color-scheme` 对得上）。
  - 失败先看：`LinuxAppearancePortal.TryReadColorSchemeIsDark` 的 `MapColorScheme`（0→null / 1→true / 2→false）与 `LinuxPlatformApp.IsDarkMode` 的回退链。

- [ ] **L1-4 切到亮色复测**
  - 命令：
    ```bash
    gsettings set org.gnome.desktop.interface color-scheme 'prefer-light'
    ```
  - 操作：等待 1 秒后重新执行 L1-3 的 Console 代码。
  - 通过判定：`dark === false`（与 L1-2 新值一致）。
  - 失败先看：同 L1-3。

- [ ] **L1-5 门户无响应时的 500ms 超时回退**
  - 命令（终端 B）：
    ```bash
    pkill -STOP -x xdg-desktop-portal
    ```
  - 操作：回到 Console 再执行 L1-3 的计时调用。
  - 通过判定：`ms < 700`（正常应约 500ms 返回），且返回值等于 gsettings 回退结果（用 `gsettings get org.gnome.desktop.interface color-scheme` 对照）；**不得永久挂起**。
  - 恢复：`pkill -CONT -x xdg-desktop-portal`
  - 失败先看：`src/Wails.Net.Application.Linux/LinuxAppearancePortal.cs` 中 500ms `CancellationTokenSource` 是否在 `Read` 与 `ReadOne` 两个分支都传入。

- [ ] **L1-6 代码审查 `ReadOne` 回退（无法在主流桌面强制触发）**
  - 命令：
    ```bash

    ```
  - 通过判定：确认 `Read` 抛 `DBusError`/方法缺失异常后会再次调用 `ReadOne`，且两个分支共用同一 500ms 超时；结论记"主路径实机验证，回退路径仅代码审查"。
  - 失败先看：同文件 `TryReadColorSchemeIsDark`。

## 6. 执行顺序建议

| 顺序 | 环境 | 合并的待办 | 说明 | 预估耗时 |
|---|---|---|---|---|
| 1 | Linux（X11 桌面） | L1 → L2 → L4 | 同一台机器、同一次登录会话即可完成：外观读取、DIP 坐标、GUI 契约；L4 建议在 L1/L2 之后跑，用契约结果交叉核对人工观察 | 90–150 分钟 |
| 2 | Linux（同一台机器，可复用构建产物） | L3 → L5 | 权限复核在 `work/` 下完成 publish/pack；然后开两个终端跑 SIGHUP/SIGTERM 清理 | 40–60 分钟 |
| 3 | macOS 实机 | M1 → M2 | 先编译验证 `#if MACOS` 分支，再以 TFM 覆盖方式构建并运行 Demo；需要授予终端「辅助功能」权限 | 45–90 分钟 |
| 4 | Windows 交互式桌面 | W1 → W2 → W3 | 一次登录完成：GUI 契约 → 托盘 Demo（重启 Explorer）→ 关闭终端窗口复测；W3 必须用独立窗口，避免误关当前会话 | 60–90 分钟 |
| 5 | Windows + Android 设备 | A1 → A3 | 工作负载安装耗时取决于网络；A1 完成后 A3 脚本会自动构建并部署 | 40–120 分钟（含下载） |

**同机合并提示**
- Linux 的 L1/L2/L4 必须同一会话（同一 `DBUS_SESSION_BUS_ADDRESS` 与同一显示器配置），否则 portal 值与缩放因子会变。
- L3 与 L1/L2 可同机但**不要同一终端**：`pack` 会重新 publish，建议在 `work/` 目录操作，避免与 Demo 运行中的 `bin/` 竞争。
- W2 的 Explorer 重启会影响整机任务栏，建议放在 W1 之后、W3 之前单独做，不要与 W3 的终端关闭测试交叉。
- Android 的 A1 与 A3 必须同机（需要 SDK/adb），A1-4 只记录结论、不阻塞 A3。
