## 修复 GitVersion “输出不是合法 JSON” 构建失败（GitHub Actions 实际运行报错）

- 报错：`Run gittools/actions/gitversion/execute@v3` → `Error: GitVersion output is not valid JSON`（GitVersion 6.8.2）。
- 根因：`gittools/actions/gitversion/execute@v3` 动作内部解析 GitVersion 6.x 输出 JSON 有 bug，吞掉底层错误仅报此信息（GitTools/actions#1824、#1576）。

  job 输出名不变，下游 build/pack/dist-* 通过 `needs.gitversion.outputs.semVer` 注入 `-p:WailsNetVersion` 不受影响。
- 额外兜底：checkout 加 `fetch-tags: true`；gitversion 步骤前 `git config --global --add safe.directory` 并 unset `extensions.worktreeConfig`，规避 LibGit2 崩溃。
- 已用 python yaml 校验：无 gittools/actions 实际引用、gitversion 作业含 dotnet-gitversion+jq+safe.directory、下游 needs/注入不变。

- 用户实际跑 CI 报错 `Invalid enum scalar 'Mainline'`：`GitVersion.yml` 的 main 分支 `mode: Mainline` 在 GitVersion 6.8.2 **不是合法枚举**（AvaloniaTemplate 用的是 `ContinuousDelivery`）。
  已修复（提交 4c8b221）：main 改回 `ContinuousDelivery`，并修正顶部注释（main 打标签后提交为补丁号递增如 1.2.4，无预发布后缀）。
  ⚠️ 切记：GitVersion 分支 `mode` 只能用 `ContinuousDelivery` / `ContinuousDeployment`（6.8.2 下无 `Mainline`）。
- 继 Mainline 之后的第二个 CI 报错：`Failed to parse 0.1.0 into a Semantic Version`（next-version 解析失败）。
  根因 = GitVersion 6.x 已知 bug（GitTools/GitVersion#3341，next-version 走独立的 Strict 字符串解析分支失败）。
  第一次修（20c661b）加 `semver-format: Loose` + 去引号 **无效**：该设置只影响 tag 解析，不作用于 next-version 解析分支（日志仍 "Format: Strict"）。
  最终修（2186c4e）：**直接删除 `next-version` 与 `semver-format`**。GitVersion 无标签/无 next-version 时自动回退默认基线 0.1.0（内部常量，不走字符串解析），既得相同起始版本又彻底避开 bug。
  "Unable to process file command 'output'" 是该解析失败的连锁报错，配置可构建后即消失。
  ⚠️ 经验：本项目 GitVersion.yml 出现 "Failed to parse X into a Semantic Version" → 直接移除 `next-version`（不要依赖 semver-format: Loose），交给默认回退基线。

- 第三个 CI 报错：NU1301 "The local source 'artifacts/nupkg' doesn't exist"（还原阶段）。
  根因：nuget.config 注册了本地源 `artifacts/nupkg`，但 CI checkout 后该目录不存在，NuGet 校验源时直接报错；且该源缺失会拖垮所有 `dotnet restore/build/run` 作业（build/test-linux/test-android/dist-* 等）。

  使 CI 每次 checkout 时 `artifacts/nupkg` 目录必然存在（空目录对 NuGet 合法），NU1301 消失；真实产物（nupkg/dist）仍被忽略。
  注意：.gitignore 必须用「先忽略目录再放行目录再忽略内容再放行文件」四行写法；`artifacts/**/*` 会把父目录也匹配成忽略导致否定失效。
  旁注：CI 的 pack 作业输出到 `artifacts/packages`（覆盖 PackageOutputPath 的 artifacts/nupkg），与本地源不一致，但 CI 上该源为空目录即可，无需改动 pack 输出路径。

## 修复 CI NETSDK1004（build / pack 缺 android 工作负载）
- 现象：GitHub Actions `windows-latest` 的 `build` 与 `pack` job 全部工程报 `NETSDK1004: Assets file '...obj/project.assets.json' not found`，随后 `dotnet build --no-restore` / `dotnet pack` 失败。

## 修复 Application.Tests 3 个失败（Geolocation 序列化 + Autostart 往返）
- **Geolocation 2 失败**（`GetCurrentPosition_WithCustomImpl_ReturnsPosition` / `_WithDefaultImpl_ReturnsNull`）：`NotSupportedException: System.IntPtr 无法序列化 ($.WaitHandle.Handle)`。
  - 根因：`GeolocationPlugin` 违反 AGENTS.md §3.4.6，把 `CancellationToken` 当成了 `MapCommand` 业务参数（`Func<ICommandContext, GeolocationOptions?, CancellationToken, Task<...>>`）。源生成器虽会把 CT 当特殊参数从 `ctx.CancellationToken` 取（不进 JSON），但 `Wails.Net.Application.Tests/CommandTestHelper.cs` 旧版会把测试传入的 `CancellationToken` 直接 `JsonSerializer.SerializeToElement` → IntPtr 崩溃。
  - 修复：对齐 `CameraPlugin` 正确写法——命令签名改为 `(ICommandContext, GeolocationOptions?, Task<GeolocationPosition?>)`，`GetCurrentPositionAsync(opts, ctx.CancellationToken)`；`watchPosition` 同理。测试去掉传入的 `CancellationToken.None`；`CommandTestHelper` 增加跳过 `CancellationToken` 参数的防御逻辑（已在工作区）。PermissionsPlugin 核对过，本就合规。
- **Autostart 1 失败**（`AutostartPlugin_EnableDisable_RoundTrip`）：`EnableAutostart` 返回 false。本地全绿（1312/0），仅 CI `windows-latest` 失败 → 环境相关。
  - 根因：`AutostartPlugin.EnableAutostartWindows` 里 `Process.GetCurrentProcess().MainModule?.FileName` 的 **`MainModule` getter 会抛异常**（CI 沙箱下 `Win32Exception`），`?.` 只防 null 接收者不防 getter 抛错，异常被外层 `catch` 吞掉返回 false，导致后面的 `Environment.ProcessPath` 回退根本走不到。
  - 修复：`ResolveExecutablePath()` 优先用不抛错的 `Environment.ProcessPath`，`MainModule` 仅在 `try/catch` 内访问，最后回退 `AppDomain.CurrentDomain.FriendlyName`；`GetAppName()`/`EnableAutostartWindows` 改用之。并给 `EnableDisable_RoundTrip` 加 `SkipTestException` 保险（环境真写不进去就跳过，与 GuiContract 测试约定一致）。
- 验证：`dotnet run -c Release tests/Wails.Net.Application.Tests` 全量 1312 通过。CI 的 `test-application`/`test-windows` 走 `dotnet run --no-build`，同源。
